# 개발 선호 사항

## 프로필
- **경력**: 풀스택 개발 8년
- **주력 언어**: TypeScript, Python
- **커뮤니케이션 스타일**: 예시를 들어 간결하게
- **학습 방식**: 시각적인 다이어그램 + 코드

## 코드 관련 선호 사항

### 에러 처리
try-catch 블록과 의미 있는 에러 메시지로 에러를 명시적으로 다루는 것을 선호합니다.
범용적인 에러는 피합니다. 디버깅을 위해 에러는 반드시 로그에 남깁니다.

### 주석
주석에는 "왜(WHY)"를 씁니다. "무엇(WHAT)"이 아닙니다. 코드는 그 자체로 문서가 되어야 합니다.
비즈니스 로직이나 자명하지 않은 판단은 주석으로 설명합니다.

### 테스트
TDD(테스트 주도 개발)를 선호합니다.
먼저 테스트를 작성하고, 그다음에 구현합니다.
구현 세부 사항이 아니라 동작에 초점을 맞춥니다.

### 아키텍처
모듈화된 느슨한 결합의 설계를 선호합니다.
테스트 용이성을 위해 의존성 주입을 사용합니다.
관심사를 분리합니다(Controllers, Services, Repositories).

## 디버깅 선호 사항
- console.log에 접두사를 붙입니다: `[DEBUG]`
- 컨텍스트를 포함합니다: 함수명, 관련 변수
- 가능하면 스택 트레이스를 사용합니다
- 로그에는 반드시 타임스탬프를 포함합니다

## 커뮤니케이션
- 복잡한 개념은 다이어그램으로 설명합니다
- 이론보다 먼저 구체적인 예시를 보여 줍니다
- 변경 전/변경 후 코드 스니펫을 포함합니다
- 마지막에 요점을 정리합니다

## 프로젝트 구성
프로젝트는 다음과 같이 정리합니다:
```
project/
  ├── src/
  │   ├── api/
  │   ├── services/
  │   ├── models/
  │   └── utils/
  ├── tests/
  ├── docs/
  └── docker/
```

## 도구
- **IDE**: VS Code(vim 키 바인딩)
- **터미널**: Zsh + Oh-My-Zsh
- **포매터**: Prettier(줄 길이 100자)
- **린터**: ESLint(airbnb config)
- **테스트 프레임워크**: Jest + React Testing Library
